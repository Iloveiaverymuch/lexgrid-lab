# ADR-003 — Evaluation tooling: Python runner for retrieval metrics, promptfoo for behaviour tests

Status: ACCEPTED · Date: 2026-11-19 · Last updated: 2026-11-19 · Next action: add LLM-answer assertions when generation lands (ROADMAP phase 4)

## Context
Two different questions need answering on every change:
1. **How good is the ranking?** Graded relevance metrics (nDCG, MRR, recall) with confidence intervals and paired
   comparisons between runs: statistics over a labelled set.
2. **Does the system behave as promised?** Scope is never widened, refusals return the right status, answers cite
   only retrieved sources, named articles come first, out-of-corpus questions are refused: pass/fail properties of
   the API, readable by people who do not read Python.

## Decision
- Keep the **Python runner** (`lexgrid eval`, `compare-runs`, `scripts/eval_gate.py`) for metrics, intervals and the
  release gate. It works on the retrieval service directly and on OpenSearch candidates before promotion.
- Add **promptfoo** for behaviour tests against the **running REST API**, through a small stdlib-only provider
  ([`evals/promptfoo/provider.py`](../../evals/promptfoo/provider.py)) that returns the HTTP status and body:
  - **contract suite** (10 tests, CI, offline server): auth, scope widening refused (also through an injection
    attempt in the query), FR key only receives FR, pinning, one result per article, every jurisdiction
    represented, citations restricted to retrieved sources, disclaimer present;
  - **quality suite** (40 tests, Mac, real models): generated from the golden set by
    [`scripts/build_promptfoo.py`](../../scripts/build_promptfoo.py) (hit@5, exact reference at rank 1, abstention).
    A test fails if it drifts from the golden set.

## Alternatives considered
| Option | Why not |
|---|---|
| promptfoo only | No graded metrics with bootstrap intervals or paired tests; cannot evaluate an unpromoted index |
| Python runner only | Behaviour checks stay buried in pytest; no shareable report; no path to LLM-graded and red-team evaluations later |
| promptfoo HTTP provider (no Python) | Non-2xx responses are harder to assert on; the custom provider keeps 401/403 as testable results |

## Consequences
- One source of truth for labels (the golden YAML); promptfoo tests are generated, never hand-edited.
- CI runs three gates: `verify` (lint, types, tests, docs), the offline retrieval regression gate, and the promptfoo
  API contract. Quality on real models stays a manual Tier-2 run on the Mac (models and OpenSearch are not in CI).
- When answers are generated by an LLM (ROADMAP phase 4), the same promptfoo suites gain groundedness and
  citation-faithfulness assertions and a red-team pass, without changing the runner.
